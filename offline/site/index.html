    YAPP Router — SystemVerilog & UVM Course¶

    The interactive project map

    Open the project map — one picture of the whole testbench and DUT you can drill into (five views: hierarchy, TLM data flow, UML classes, the environment and the test plan), generated from the source, with the regression and coverage results on every card. Also available as a single offline HTML file.

    This site is the companion to the YAPP packet-router verification project: a complete UVM environment built from scratch over eleven labs, exactly the way a verification engineer would build one at work — one component at a time, each one tested before the next is added.

    Everything here is a reference solution: the DUT, every UVM verification component (UVC), every lab in its finished state, the register model, the coverage model and the tests. The code is written to be read: short files, one idea per class, comments that say why.

      The YAPP router: one packet input, three output channels, a host bus and a handful of registers. Small enough to understand completely, rich enough to need a real environment.

    • :material-sitemap:{ .lg .middle } UVM, the big picture

    • :material-puzzle:{ .lg .middle } Component guides

      One page per building block: packet, driver, sequencer, monitor, agent, scoreboard, reference model, virtual sequencer, coverage, register model.

      Labs 1 to 11C, each with objective, concepts, diagrams, the full solution, the tests to run, checkpoint questions with answers and the expected result.

    How to use this site¶

    1. Read Getting started once and run test_install (Xcelium) — or, without a licence, open the repository in a GitHub Codespace and run make sim (Verilator: the same labs, the same tests, free).
    2. Read the DUT specification: every lab assumes you know the packet format and the three port protocols.
    3. Work through the labs in order. Each lab page tells you what to build, why, and what the simulation must show when you are done. Try to write the code yourself first; the solution is there when you get stuck or want to compare.
    4. Use the component guides when a piece of UVM does not click: they explain the same code from the "what is a driver" angle instead of the "lab step 4" angle.
    • The labs overview has the session plan, the dependency chain and what each lab adds.
    • Every lab page ends with checkpoint questions; the answers are in collapsible boxes so you can use them for reviews.
    • labs/<lab>/ is a complete snapshot of the code at the end of that lab. diff -r labs/lab04_factory labs/lab05_seq shows exactly what a lab adds.
    • The test plan maps DUT features to tests and checkers, the regression results and coverage results show what the last regression did, and the verification status page lists what the Verilator runs proved and what still needs Xcelium.

    What is in the repository¶

    yapp_project/                the complete project, the state after Lab 11C (source of truth)
├── rtl/                     the DUT, one module per file (yapp_router.sv + yapp_router.f)
├── uvc/yapp/                YAPP input UVC   -- built in Labs 1-6, final state
├── uvc/hbus/                HBUS UVC         -- "provided"
├── uvc/channel/             Channel UVC      -- "provided"
├── uvc/clock_and_reset/     Clock & Reset UVC-- "provided"
├── uvc/router/              router module UVC (scoreboard, reference model, coverage collectors) -- Labs 9A-9D
├── tb/                      the final testbench: tests/, mcseqs/, reg/, run.f, Makefile, the DUT tracer
└── regression/              the committed report of the last regression: logs, timelines, waves, coverage
labs/<lab>/                  one snapshot per lab (sv/ in Labs 1-6 and 9A-9D, tb/, run.f, Makefile);
                             Labs 7+ compile the YAPP UVC and the DUT from yapp_project/
common/                      what every bench shares: rand_util_pkg (rnd::), lab.mk, the Verilator glue
test_install/                does the simulator find UVM?
scripts/                     lint harness (slang), Verilator flow (sim.py, regress.yaml), the regression
                             and coverage reports, the project-map generator, the waveform generator
docs/                        this site

    About the original material

    The project follows the structure of the Cadence SystemVerilog Accelerated Verification Using UVM training. No Cadence files are used: the DUT, the "provided" UVCs, the interfaces and the register model were all written for this repository from the public specification of the exercise.
