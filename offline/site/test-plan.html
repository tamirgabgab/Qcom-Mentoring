    Test plan¶

    Open the Test plan view of the project map →

    A verification plan links every feature of the DUT to the stimulus that exercises it, the checker that judges it and the coverage that proves it happened. This plan follows the pages of the course's DUT description (packet format, input and output protocols, registers, drop rules, counters, memories, host port) and the lab chapters that add requirements of their own (scoreboard, functional coverage, register tests). 12 feature groups, 64 items: 63 covered, 1 excluded.

    Every item says what is driven, what is checked and by which test; a partial item is exercised but not fully checked, a gap has no test yet (the note says what one would do), an excluded item is left out on purpose. The same data drives the Test plan view of the project map, where every test card lists the items it verifies.

    Features¶

    PKT — Packet format¶

    Header {length[7:2], addr[1:0]}, 1..63 payload bytes, one even-parity byte over header and payload; address 3 is illegal. Project Overview p. 6 -- Packet Data Specification. Read the specification → On the map →

    Item What is verified, and how Tests
    PKT-01
    covered    		 Header: length in [7:2], address in [1:0]
    Stimulus: Every packet; the driver packs {length, addr}, the channel monitor unpacks it again.
    Check: The channel monitor's length and address equal the YAPP packet's (scoreboard compare, channel address check); the DUT reads length + 2 bytes exactly, so the next header is found where the monitor expects it.    		 simple_test
    router_simple_mcseq_test
    coverage_test
    PKT-02
    covered    		 Every payload length 1..63, including both extremes
    Stimulus: yapp_coverage_seq sends 1, 5, 20, 50 and 63 bytes; random sequences cover the rest; backpressure_test sends 40..63.
    Check: Scoreboard compare; a wrong length would shift the parity byte and the monitors would disagree.
    Coverage: length_cp bins MIN, SMALL, MEDIUM, LARGE, MAX    		 coverage_test
    scoreboard_drop_test
    backpressure_test
    random_test
    PKT-03
    covered    		 Address 3 is illegal
    Stimulus: Packets with addr == 3 (c_addr_legal switched off): yapp_88_packets_seq, yapp_coverage_seq, yapp_boundary_seq.
    Check: No byte appears on any channel (scoreboard: nothing unexpected), the reference model drops it, addr3_cnt_reg counts it when addr3_cnt_en is set.
    Coverage: addr_cp.illegal_addr    		 test_uvc_integration
    coverage_test
    router_filter_test
    random_config_test
    PKT-04
    covered    		 Even bitwise parity over header and payload
    Stimulus: Every good packet: parity = XOR of the header and all payload bytes (yapp_packet::calc_parity).
    Check: The channel monitor recomputes the parity and tags the packet CHANNEL_PARITY_TYPE_GOOD; the DUT counts nothing in parity_err_cnt_reg; no error pulse.
    Coverage: parity_cp    		 reg_function_test
    coverage_test
    router_filter_test
    PKT-05
    covered    		 A wrong parity byte is detected -- and the packet still delivered
    Stimulus: m_parity_type == PARITY_TYPE_BAD flips one bit of the correct parity (yapp_pkt_seq, yapp_coverage_seq, 20 % in yapp_88_packets_seq).
    Check: parity_err_cnt_reg equals the monitor's num_bad_parity; error pulses once per bad packet (error_pulse_checker); the scoreboard still matches the packet (the router forwards it -- see Decisions in dut/spec.md).
    Coverage: parity_cp, len_x_addr_x_parity (REQ3)    		 reg_function_test
    parity_error_test
    test_uvc_integration
    random_parity_test

    IN — Input port protocol¶

    Driven on the falling edge, sampled on the rising edge; in_data_vld frames header and payload; in_suspend stalls the sender; error pulses 1..10 cycles after a bad packet. Project Overview p. 7 -- Input Port Protocol. Read the specification → On the map →

    Item What is verified, and how Tests
    IN-01
    covered    		 in_data_vld rises with the header; one byte per falling edge
    Stimulus: yapp_if.send_to_dut in every packet test.
    Check: DUT, driver and monitor agree on one rule -- a byte is accepted at a rising edge with in_suspend low; a disagreement shows as a parity error or a scoreboard mismatch.    		 yapp_012_test
    simple_test
    coverage_test
    IN-02
    covered    		 in_data_vld is low with the parity byte
    Stimulus: Every packet: the driver drops in_data_vld on the falling edge after the last payload byte.
    Check: The DUT's PARITY state takes the next accepted byte regardless of in_data_vld; the monitor samples the parity the same way; the packet count in the DUT (mem_size_reg, counters) matches.    		 simple_test
    reg_function_test
    pkt_mem_test
    IN-03
    covered    		 in_suspend: the input holds while the target FIFO is full
    Stimulus: Slow receivers (channel_rx_slow_seq, 20..40 cycles) and 40..63-byte packets, so the 16-byte FIFO fills before the receiver starts.
    Check: in_suspend rose at least once; scoreboard 6 matched, 0 mismatched, 0 unexpected; no parity error at the monitor (every byte accepted exactly once).
    Note: Writing this test showed that yapp_if.wait_accept() sampled in_suspend on the falling edge; it now samples the rising edge, like the DUT and the monitor (see components/driver.md).    		 backpressure_test
    random_backpressure_test
    IN-04
    covered    		 error asserts 1 to 10 cycles after a bad-parity packet
    Stimulus: 12 packets with bad parity (parity_error_test); in random_parity_test bad packets on forwarded and dropped packets and storms of 1..3-byte bad packets back to back.
    Check: error_pulse_checker: one pulse per bad packet received while enabled, 1..10 cycles after its parity byte; overlapping bad packets each get their own pulse (owed pulses are a queue); a pulse with nothing owed, an owed pulse older than 10 cycles, or one still owed at the end is an error.
    Note: The random storms found that a second bad packet ending before the first pulse re-armed the timer and the first pulse was lost; yapp_error_timer now schedules one pulse per packet (dut/rtl.md).    		 parity_error_test
    test_uvc_integration
    random_parity_test

    OUT — Output port protocol¶

    16-byte FIFO per channel; data_vld_x with the byte, the receiver reads on the falling edge and de-asserts suspend_x; a new byte every rising edge while suspend_x is low. Project Overview p. 8 -- Output Port Protocol (Channel Ports). Read the specification → On the map →

    Item What is verified, and how Tests
    OUT-01
    covered    		 data_vld_x, suspend_x and one byte per rising edge
    Stimulus: channel_if.receive_packet in every scoreboard test: the receiver reads length + 2 bytes after it drops suspend_x.
    Check: The channel monitor collects exactly length + 2 bytes (a wrong handshake would duplicate or skip a byte and the scoreboard would mismatch); the address check never fires.    		 simple_test
    router_simple_mcseq_test
    coverage_test
    OUT-02
    covered    		 The receiver may answer late: the header is held
    Stimulus: channel_rx_resp_seq: response delay 0..10 cycles per packet; channel_rx_slow_seq: 20..40.
    Check: Scoreboard compare: the header read after the delay is still the header.    		 simple_test
    router_simple_mcseq_test
    backpressure_test
    random_backpressure_test
    OUT-03
    covered    		 The FIFO is 16 bytes deep
    Stimulus: Packets longer than 16 bytes with a receiver that waits 20..40 cycles: the FIFO fills, the router stalls the input.
    Check: in_suspend seen (backpressure_test); no byte lost (scoreboard); the FIFO never overflows (a lost byte would show as a parity error).    		 backpressure_test
    scoreboard_drop_test
    OUT-04
    covered    		 suspend_x is re-asserted at the parity byte: the next packet waits
    Stimulus: Back-to-back packets to the same channel (0,1,2,0,1,2 and the boundary sequence).
    Check: The second packet's header is held in the FIFO until the receiver answers again; the scoreboard matches both in order.    		 router_simple_mcseq_test
    router_filter_test
    backpressure_test
    OUT-05
    covered    		 All three channels busy at the same time
    Stimulus: Random addresses with slow receivers: packets to channels 0, 1 and 2 are in flight together.
    Check: Scoreboard: every channel matched, nothing unexpected.    		 backpressure_test
    coverage_test
    random_backpressure_test

    REG — Registers¶

    ctrl_reg (maxpktsize) and en_reg are RW, the six counters and mem_size_reg are RO; reset values 0x3f, 0x01 and 0x00. Project Overview p. 9, Lab 11 p. 49 -- Packet Router DUT Registers. Read the specification → On the map →

    Item What is verified, and how Tests
    REG-01
    covered    		 Reset values
    Stimulus: uvm_reg_hw_reset_seq reads every register right after reset.
    Check: The built-in sequence compares each read with the model's reset value: ctrl_reg 0x3f, en_reg 0x01, counters and mem_size_reg 0x00.    		 uvm_reset_test
    REG-02
    covered    		 RW registers: every bit can be written and read back
    Stimulus: Walking one, walking zero, 0x00, 0xff, 0xaa, 0x55 through ctrl_reg and en_reg (20 patterns each).
    Check: After each write the front-door read and the backdoor peek return the pattern; the reserved bits ctrl_reg[7:6] and en_reg[3] hold their value (they are RW in the router).    		 reg_bit_walk_test
    reg_access_test
    REG-03
    covered    		 RO registers ignore writes
    Stimulus: Front-door writes to every counter and to mem_size_reg (register model) and a raw HBUS write to 0x1004.
    Check: peek after the write shows the poked value, the read shows 0x00 after the raw write.    		 reg_access_test
    reg_introspection_test
    reg_bit_walk_test
    hbus_protocol_test
    REG-04
    covered    		 Front door and backdoor see the same flip-flops
    Stimulus: write -> peek and poke -> read on a RW register; poke -> read on a RO register (-access +rwc).
    Check: The values agree; the HDL paths of the model (hw_top.dut.u_regs.) resolve.    		 reg_access_test
    reg_introspection_test
    REG-05
    covered    		 Unmapped addresses read 0x00 and ignore writes
    Stimulus: Write 0xa5 then read 0x1002, 0x1003, 0x1007, 0x1008, 0x100c, 0x100e, 0x100f and 0x1050 with raw HBUS sequences.
    Check: Every read returns 0x00.    		 hbus_protocol_test
    random_test
    hbus_sweep_test
    REG-06
    covered    		 mem_size_reg holds the payload length of the last packet
    Stimulus: A 20-byte packet, then a 9-byte packet that is dropped as oversized.
    Check: mem_size_reg reads 20, then 9 (only bits [5:0] are used).    		 pkt_mem_test
    random_test
    REG-07
    covered    		 Automatic checking on read (check_on_read + predict)
    Stimulus: The reg_function_test stimulus with set_check_on_read(1); predict() loads the expected counter before each read.
    Check: The map compares every read with the mirror and raises UVM_ERROR on a difference.    		 reg_function_check_test

    DROP — Drop rules¶

    The whole packet is dropped when length > maxpktsize, when the router is disabled, or when the address is 3; changing the enables mid-packet is undefined. Project Overview p. 10 -- maxpktsize, router_en, counters. Read the specification → On the map →

    Item What is verified, and how Tests
    DROP-01
    covered    		 length > maxpktsize drops the whole packet
    Stimulus: maxpktsize = 20 with full-size packets (scoreboard_drop_test, test_uvc_integration); maxpktsize = 10 with lengths 9, 10, 11 and 63 (router_filter_test).
    Check: Nothing of the packet appears on the channel: the reference model drops it and the scoreboard sees nothing unexpected; ROUTER DROPS PACKET ... length > maxpktsize; length == maxpktsize still passes.    		 router_filter_test
    scoreboard_drop_test
    test_uvc_integration
    random_config_test
    DROP-02
    covered    		 router_en = 0 drops every packet
    Stimulus: en_reg = 0xfe, then yapp_012_seq; en_reg = 0xff, yapp_012_seq again.
    Check: Channel monitors collect nothing while disabled, the reference model reports 3 dropped (router disabled), no counter and not mem_size_reg moves; after re-enabling the packets flow and the address counters read 1.    		 router_disable_test
    random_config_test
    DROP-03
    covered    		 Address 3 drops the packet
    Stimulus: As PKT-03.
    Check: Reference model drop, no unexpected channel packet, ROUTER DROPS PACKET ... illegal address.    		 router_filter_test
    coverage_test
    test_uvc_integration
    random_config_test
    DROP-04
    covered    		 An oversized packet to address 3 counts in both counters
    Stimulus: The 11- and 63-byte packets to address 3 of yapp_boundary_seq.
    Check: oversized_pkt_cnt_reg counts them and addr3_cnt_reg counts them (the DUT evaluates the conditions independently -- see Decisions in dut/spec.md).    		 router_filter_test
    random_config_test
    DROP-05
    excluded    		 Changing router_en or a counter enable in the middle of a packet
    Note: The specification declares the behaviour undefined, so no test drives it; every test programs the registers between packets.    		 —

    CNT — Counters¶

    Six 8-bit counters, each behind an enable bit of en_reg: parity errors, oversized packets, and one per address including the illegal 3. Project Overview p. 10 -- The router counters. Read the specification → On the map →

    Item What is verified, and how Tests
    CNT-01
    covered    		 A counter counts only while its enable bit is set
    Stimulus: en_reg = 0x01 then 0xff around yapp_012_seq (address counters); 0xff then 0x01 around yapp_boundary_seq (oversized, addr3, addrN); 0x03 then 0x01 around bad packets (parity).
    Check: The counters read 0 (or stay frozen) while disabled and the exact packet count while enabled.    		 reg_function_test
    router_filter_test
    parity_error_test
    random_config_test
    CNT-02
    covered    		 addrN_cnt_reg counts every received packet with address N
    Stimulus: yapp_boundary_seq: 4 packets per address, half of them dropped as oversized.
    Check: addr0/1/2_cnt_reg read 4 each: dropped packets are counted too (they were received -- see Decisions); yapp_012_seq twice gives 2 each.    		 router_filter_test
    reg_function_test
    random_config_test
    CNT-03
    covered    		 parity_err_cnt_reg counts the bad-parity packets
    Stimulus: yapp_012_seq twice (random parity) and 8 + 4 deliberately bad packets.
    Check: The register equals the YAPP monitor's num_bad_parity delta, then 8, then still 8 with the enable off.    		 reg_function_test
    parity_error_test
    random_parity_test
    CNT-04
    covered    		 oversized_pkt_cnt_reg counts packets longer than maxpktsize
    Stimulus: 8 oversized packets of yapp_boundary_seq (11 and 63 bytes against maxpktsize 10); none in reg_function_test (maxpktsize 63).
    Check: Reads 8, then 0 in reg_function_test.    		 router_filter_test
    reg_function_test
    random_config_test
    CNT-05
    covered    		 addr3_cnt_reg counts packets to address 3
    Stimulus: 4 packets to address 3 (yapp_boundary_seq); none in yapp_012_seq.
    Check: Reads 4, and 0 in reg_function_test.    		 router_filter_test
    reg_function_test
    random_config_test
    CNT-06
    covered    		 Counter overflow after 255 packets
    Stimulus: 257 one-byte packets to address 0 with every counter enabled.
    Check: addr0_cnt_reg reads 255 after 255 packets, 0 after the 256th (it wraps, it does not saturate), 1 after the 257th.
    Note: The specification is silent; wrapping is the decision recorded in dut/spec.md. Every counter is the same + 8'd1 in yapp_hbus_regs, so one counter stands for all six.    		 counter_wrap_test
    hbus_sweep_test

    MEM — Memories¶

    Item What is verified, and how Tests
    MEM-01
    covered    		 yapp_pkt_mem holds the last packet, byte by byte

    Check: yapp_pkt_mem[0] == {length, addr}, yapp_pkt_mem[1..20] == payload[0..19], read through the register model.    		 pkt_mem_test
    random_test
    MEM-02
    covered    		 yapp_pkt_mem is read-only
    Stimulus: A raw HBUS write to 0x1010 with the inverted header.
    Check: yapp_pkt_mem[0] still reads the header.    		 pkt_mem_test
    hbus_sweep_test
    MEM-03
    covered    		 A dropped packet is still stored
    Stimulus: maxpktsize = 5 and a 9-byte packet.
    Check: mem_size_reg reads 9 and the bytes are in yapp_pkt_mem: the packet was received, just not forwarded (Decisions in dut/spec.md).    		 pkt_mem_test
    random_config_test
    MEM-04
    covered    		 yapp_mem: every byte can be written and read back
    Stimulus: uvm_mem_walk_seq: writes and reads the 256 bytes with a walking pattern; with +define+INJECT_ERROR the RTL flips bit 3 of address 0x2a.
    Check: The built-in sequence compares; 0 errors without the define, one UVM_ERROR with it (yapp_mem[42]). The regression runs both builds; the second one passes only if the error is reported.    		 uvm_mem_walk_test

    HBUS — Host port (HBUS)¶

    One-cycle writes and two-cycle reads driven on the falling edge; hdata is bidirectional and tri-stated by the DUT when hen is low. Project Overview p. 11 -- Host Interface Port Protocol. Read the specification → On the map →

    Item What is verified, and how Tests
    HBUS-01
    covered    		 Write: hen and hwr_rd for one cycle, data latched on the rising edge
    Stimulus: Every register write (hbus_if.hbus_write): raw sequences and the register model's front door.
    Check: The value is read back (hbus_protocol_test, every reg test); the HBUS monitor decodes one WRITE per access.    		 hbus_protocol_test
    router_simple_mcseq_test
    reg_access_test
    HBUS-02
    covered    		 Read: haddr sampled in cycle 1, hdata driven by the DUT in cycle 2
    Stimulus: Every register read (hbus_if.hbus_read); hbus_read_max_pkt_seq after each maxpktsize write.
    Check: The value read equals what was written or poked (20 and 63 in router_simple_mcseq_test, 0x2a in hbus_protocol_test); the monitor decodes one READ.    		 hbus_protocol_test
    router_simple_mcseq_test
    reg_access_test
    HBUS-03
    covered    		 hdata is tri-stated when hen drops
    Stimulus: A read, then two idle cycles.
    Check: hbus_if.hdata_w reads 'z (the master's output enable is off, so only the DUT could still drive it).    		 hbus_protocol_test
    HBUS-04
    covered    		 Back-to-back accesses
    Stimulus: uvm_mem_walk_seq (511 writes and 255 reads with no gap), the 20-pattern walks of reg_bit_walk_test.
    Check: Every read returns the expected value; the monitor count equals the number of accesses.    		 uvm_mem_walk_test
    reg_bit_walk_test
    HBUS-05
    covered    		 The register model's front door is HBUS traffic
    Stimulus: write()/read() through yapp_rm.default_map and the hbus_reg_adapter.
    Check: The HBUS monitor logs the cycles, and the reference model mirrors maxpktsize and router_en from them (the drop rules follow the model's writes in router_disable_test and router_filter_test).    		 reg_function_test
    router_disable_test
    router_filter_test

    RND — Random scenarios¶

    Random tests whose seed decides the shape: packet count, bursts, configuration, receiver profiles; every result checked by the reference model, the scoreboard and the error-pulse checker. Project Overview pp. 5-11 -- every rule at once, in random combinations. Read the specification → On the map →

    Item What is verified, and how Tests
    RND-01
    covered    		 Random configuration between bursts
    Stimulus: router_random_mcseq: before each burst a random ctrl_reg (maxpktsize 0, 1, 62, 63 often, bits [7:6] random) and en_reg (router off now and then, counter-enable masks all / none / random).
    Check: router_reference models the counters, mem_size_reg, yapp_pkt_mem and yapp_mem and checks every HBUS read (check_reads = 1): random reads after each configuration, every register and the stored packet at the end.
    Coverage: router_coverage router_cfg_cg: maxpktsize, length vs maxpktsize, drop reason x parity, counter enables    		 random_test
    random_config_test
    RND-02
    covered    		 One error pulse per bad packet when bad packets overlap
    Stimulus: random_parity_test storms: 1..3-byte packets, 90% back to back, half with bad parity.
    Check: error_pulse_checker matches every cycle with error high to the oldest owed pulse (1..10 cycles); nothing owed at the end.    		 random_parity_test
    RND-03
    covered    		 Bad parity on dropped and ignored packets
    Stimulus: Bad parity on packets to address 3, oversized packets and packets sent with the router off.
    Check: Dropped bad packets count in parity_err_cnt_reg (enable bit) and pulse; with the router off nothing counts or pulses (reference model, error_pulse_checker).    		 random_parity_test
    random_config_test
    RND-04
    covered    		 Receivers that stall, per channel
    Stimulus: channel_rx_random_seq per channel: fast, normal, slow (20..40) or stalling (50..150 cycles now and then), before a packet, never in the middle.
    Check: Scoreboard: every forwarded byte out once and in order; nothing left in the queues at the end (check_phase).    		 random_backpressure_test
    random_test

    COV — Functional coverage¶

    The coverage models: yapp_pkt_coverage (Lab 10: length buckets, every address including the illegal one, every length to every legal address with bad parity) and the HBUS collectors of the router module (address map, register bits, yapp_mem data, counter values). Lab 10 p. 47 -- REQ1, REQ2, REQ3. The lab → On the map →

    Item What is verified, and how Tests
    COV-01
    covered    		 REQ1: all packet lengths, bucketed
    Stimulus: yapp_coverage_seq: 1, 5, 20, 50, 63.
    Check: length_cp bins MIN, SMALL, MEDIUM, LARGE, MAX all hit; the pkt_cov report prints 100 %.
    Coverage: length_cp    		 coverage_test

    Writing a new test — checklist¶

    1. Extend base_test (or reg_function_test when you need the register block, the YAPP sequencer and check_counter()); add `uvm_component_utils and the constructor.
    2. Decide the packet type: factory override in build_phase before super.build_phase(phase).
    3. configure_sequences(): which sequencer runs what. Always set_clock_and_channel_sequences() in Labs 7+ (or your own channel sequence, as backpressure_test does).
    4. For register tests: get handles in connect_phase, raise an objection in run_phase, use the model API.
    5. Decide what passes: UVM_ERROR : 0 plus the counts in the reports, and say so in the log (uvm_info at UVM_NONE).
    6. Add the test to annotations.yaml: a line under classes:, its plan under tests:, and the items it verifies under plan:; make map regenerates this page and the map.
