    Functional coverage¶

    Open on the project map →

    Functional coverage answers "did we exercise what we meant to?" — not whether the DUT was right (that is the scoreboard's job). It samples what the monitors publish (the YAPP packets, the HBUS cycles) and what the reference model decided, because they see what actually happened on the bus, whatever the sequences intended.

    Where the covergroups live¶

    Every covergroup has its own file: a coverage collector, a uvm_subscriber that holds one covergroup and samples it in write(). The monitor and the reference model only publish on an analysis port; the collectors subscribe.

    flowchart LR
    MON["yapp_tx_monitor"] -->|"item_collected_port"| PKT["pkt_cov<br/>yapp_pkt_coverage<br/>yapp_pkt_cg"]
    MON -->|"item_collected_port"| GAP["gap_cov<br/>yapp_gap_coverage<br/>yapp_gap_cg"]
    MON -->|"item_collected_port"| REF["router_reference"]
    REF -->|"decision_out<br/>(router_decision)"| RC["coverage<br/>router_coverage<br/>router_cfg_cg"]
    HM["hbus_monitor"] -->|"hbus_export"| REF
    HM -->|"hbus_export"| HC["hbus_addr_cov · hbus_bits_cov<br/>hbus_data_cov · hbus_counter_cov"]
    Collector (instance) File Covergroup Samples
    tb.yapp.agent.pkt_cov yapp_project/uvc/yapp/yapp_pkt_coverage.sv yapp_pkt_cg (Lab 10) length, address, parity of every input packet
    tb.yapp.agent.gap_cov yapp_project/uvc/yapp/yapp_gap_coverage.sv yapp_gap_cg (ROUTE-04) the gap before every packet, which the monitor writes into packet_delay
    tb.router_module.coverage yapp_project/uvc/router/router_coverage.sv router_cfg_cg (random tests) maxpktsize, length vs maxpktsize, drop reason × parity, counter enables of every packet received while the router is on, from the reference's router_decision
    tb.router_module.hbus_addr_cov yapp_project/uvc/router/router_hbus_addr_coverage.sv hbus_addr_cg (COV-04) the address of every HBUS access × read / write
    tb.router_module.hbus_bits_cov yapp_project/uvc/router/router_hbus_bits_coverage.sv hbus_bits_cg (COV-05) every bit of every write to ctrl_reg / en_reg
    tb.router_module.hbus_data_cov yapp_project/uvc/router/router_hbus_data_coverage.sv hbus_data_cg (COV-06) the byte of every access to yapp_mem × read / write
    tb.router_module.hbus_counter_cov yapp_project/uvc/router/router_hbus_counter_coverage.sv hbus_counter_cg (COV-07) the value every counter read returned

    Why not inside the monitor, as the Cadence lab writes it? The monitor's job is to observe and publish. A separate collector can be added, replaced (factory) or left out without touching the monitor, a passive agent keeps it, and a collector can sample what another component decided (the reference model's drop reason), which the monitor never sees. The bins are the same, so the percentage is the same.

    HBUS coverage¶

    The four HBUS collectors subscribe to router_module_env.hbus_export, next to the reference model. They live in the router module UVC, not in the HBUS UVC: the HBUS UVC is generic, the address map belongs to the router.

    Covergroup Coverpoints Bins
    hbus_addr_cg addr_cp: the 9 registers, the 7 holes between them (reg_hole[]: 0x1002, 0x1003, 0x1007, 0x1008, 0x100c, 0x100e, 0x100f), first / middle / last byte of yapp_pkt_mem (0x1010..0x104f), of the unmapped range 0x1050..0x10ff and of yapp_mem (0x1100..0x11ff); rw_cp: read, write 25 + 2, cross addr_x_rw 50
    hbus_bits_cg sampled once per bit of every write to ctrl_reg / en_reg: reg_cp (ctrl, en) × bit_cp (b[0..7]) × val_cp (0, 1) cross 32
    hbus_data_cg accesses to yapp_mem: rw_cp × pattern_cp (0x00, 0xff, 0x55, 0xaa, other) cross 10
    hbus_counter_cg reads of a counter: counter_cp (parity, oversized, addr0..addr3) × value_cp (0, 1..254, 255) cross 18

    hbus_sweep_test (router_hbus_sweep_mcseq) closes them: it writes and reads every address of the window, reads the whole register window back after each write to a register, a hole or a read-only byte (so a write that lands on the wrong register is caught), walks the bits of ctrl_reg / en_reg, fills yapp_mem with the four patterns and a random value, and sends 1020 two-byte bad-parity packets (oversized at maxpktsize = 1, so dropped) to take every counter to 255. Every read is checked by the reference model (check_reads = 1), and the test fails unless the four covergroups reach 100 %. Making the RTL write ctrl_reg on a write to the hole 0x1002 makes it fail with HBUS read 0x1000 returned 0x00, the model expects 0xaa.

    The requirements (Lab 10)¶

    Req Statement Coverpoint / cross
    REQ1 every packet length, bucketed length_cp: MIN=1, SMALL=[2:10], MEDIUM=[11:40], LARGE=[41:62], MAX=63
    REQ2 every address, including the illegal one addr_cp: legal[] = {[0:2]}, illegal_addr = {3}
    REQ3 every length bucket to every legal address with a parity error len_x_addr_x_parity cross, ignoring GOOD_PARITY and illegal_addr

    The covergroup¶

    covergroup yapp_pkt_cg with function sample(bit [5:0] length,
                                            bit [1:0] addr,
                                            parity_type_e parity_type);
  option.per_instance = 1;
  length_cp : coverpoint length {
    bins MIN    = {1};
    bins SMALL  = {[2:10]};
    bins MEDIUM = {[11:40]};
    bins LARGE  = {[41:62]};
    bins MAX    = {63};
  }
  addr_cp : coverpoint addr {
    bins legal[]      = {[0:2]};
    bins illegal_addr = {3};
  }
  parity_cp : coverpoint parity_type {
    bins good = {GOOD_PARITY};
    bins bad  = {BAD_PARITY};
  }
  len_x_addr_x_parity : cross length_cp, addr_cp, parity_cp {
    ignore_bins good_parity  = binsof(parity_cp) intersect {GOOD_PARITY};
    ignore_bins illegal_addr = binsof(addr_cp.illegal_addr);
  }
endgroup
    • Inside a class a covergroup is created in the constructor — yapp_pkt_cg = new(); — no separate variable.
    • with function sample(...) lets the collector pass the values explicitly; the alternative is coverpoints on class members sampled with sample().
    • illegal_addr is a normal bin, not illegal_bins: REQ2 wants to count packets to address 3, not flag them as errors.
    • The cross is restricted with ignore_bins so that only the combinations REQ3 cares about count towards 100%: 5 lengths × 3 addresses × BAD_PARITY = 15 bins.
    • parity_cp names its two bins. An enum coverpoint without bins gets one bin per value on Xcelium, but Verilator bins it by value range.
    • Verilator ignores ignore_bins written with binsof() intersect, so under `ifdef VERILATOR the collector builds the same 15-bin cross from two extra coverpoints that hold only the legal addresses and only BAD_PARITY -- see Simulating with Verilator.

    Sampling¶

    yapp_pkt_coverage::write(t) calls yapp_pkt_cg.sample(t.length, t.addr, t.parity_type) for every packet the monitor publishes:

    //------------------------------------------------------------------------------
// yapp_pkt_coverage.sv -- functional coverage of the input packets (Lab 10)
//
//   yapp_tx_monitor.item_collected_port ──► analysis_export (write)
//
// The covergroup lives in its own subscriber, not in the monitor: the monitor
// only observes and publishes, and a coverage model can be added, replaced or
// left out without touching it. The Cadence lab writes the same covergroup
// inside the monitor; the bins, and so the percentage, are the same.
//------------------------------------------------------------------------------
class yapp_pkt_coverage extends uvm_subscriber #(yapp_packet);

  int num_sampled;

  //--------------------------------------------------------------------------
  // Functional coverage (Lab 10)
  //   REQ1 all packet lengths, bucketed
  //   REQ2 all addresses, including the illegal one
  //   REQ3 every length bucket to every legal address with a parity error
  //--------------------------------------------------------------------------
  covergroup yapp_pkt_cg with function sample(bit [5:0] length,
                                              bit [1:0] addr,
                                              parity_type_e parity_type);
    option.per_instance = 1;
    length_cp : coverpoint length {
      bins MIN    = {1};
      bins SMALL  = {[2:10]};
      bins MEDIUM = {[11:40]};
      bins LARGE  = {[41:62]};
      bins MAX    = {63};
    }
    addr_cp : coverpoint addr {
      bins legal[]      = {[0:2]};
      bins illegal_addr = {3};
    }
    // one bin per enum value, written out (Verilator 5.052 bins an enum by range)
    parity_cp : coverpoint parity_type {
      bins good = {GOOD_PARITY};
      bins bad  = {BAD_PARITY};
    }
    // REQ3: only legal addresses and only BAD_PARITY are interesting
`ifdef VERILATOR
    // (Verilator 5.052 drops ignore_bins with binsof/intersect, so the cross is
    // built from coverpoints that hold only the interesting bins: same 15 bins)
    legal_addr_cp : coverpoint addr { bins legal[] = {[0:2]}; }
    bad_parity_cp : coverpoint parity_type { bins bad = {BAD_PARITY}; }
    len_x_addr_x_parity : cross length_cp, legal_addr_cp, bad_parity_cp;
`else
    len_x_addr_x_parity : cross length_cp, addr_cp, parity_cp {
      ignore_bins good_parity  = binsof(parity_cp) intersect {GOOD_PARITY};
      ignore_bins illegal_addr = binsof(addr_cp.illegal_addr);
    }
`endif
  endgroup : yapp_pkt_cg

  `uvm_component_utils(yapp_pkt_coverage)

  extern function new(string name, uvm_component parent);

  // One packet from the monitor
  extern function void write(yapp_packet t);

  extern function void report_phase(uvm_phase phase);

endclass : yapp_pkt_coverage

//------------------------------------------------------------------------------
// yapp_pkt_coverage -- method implementations
//------------------------------------------------------------------------------

function yapp_pkt_coverage::new(string name, uvm_component parent);
  super.new(name, parent);
  yapp_pkt_cg = new();   // a covergroup inside a class is created with new()
endfunction : new

//------------------------------------------------------------------------------
function void yapp_pkt_coverage::write(yapp_packet t);
  num_sampled++;
  yapp_pkt_cg.sample(t.length, t.addr, t.parity_type);
endfunction : write

//------------------------------------------------------------------------------
function void yapp_pkt_coverage::report_phase(uvm_phase phase);
  `uvm_info(get_type_name(), $sformatf("YAPP packet coverage: %0d packets sampled, coverage %.1f%%",
                                       num_sampled, yapp_pkt_cg.get_inst_coverage()), UVM_LOW)
endfunction : report_phase

    The agent builds the collectors and connects them (yapp_tx_agent):

    monitor.item_collected_port.connect(pkt_cov.analysis_export);
monitor.item_collected_port.connect(gap_cov.analysis_export);

    Closing the holes¶

    Test Covers Misses
    router_simple_mcseq_test (short packets) MIN, SMALL, some MEDIUM; addresses 0–2 LARGE, MAX, address 3, most of the cross
    test_uvc_integration (88 packets, lengths 1–22) all addresses incl. 3 LARGE, MAX
    coverage_test → yapp_coverage_seq everything: each length bucket × each address × good/bad parity (40 packets) —

    yapp_coverage_seq is the "modify your stimulus to achieve coverage" step of the lab. Run it with several seeds (+SVSEED=random) and merge the results in IMC to see 100% on the three requirements.

    Seeing the results (Verilator)¶

    Every Verilator run collects functional coverage: scripts/sim.py compiles with --coverage-user (the covergroup bins only, no line or toggle coverage) and each run writes its bins to build/sim/<bench>/coverage/<test>_s<seed>.dat. Three places show them:

    1. The log of one run. Each collector prints its percentage in report_phase:

      [yapp_pkt_coverage] YAPP packet coverage: 22 packets sampled, coverage 60.0%
[yapp_gap_coverage] YAPP gap coverage: 21 gaps sampled, coverage 100.0%
[router_coverage] Coverage of the router configuration: 65.2%

    2. The whole regression, merged. After make regress:

      make coverage ONLY=yapp_project      # summary and the holes, in the terminal
make sim-report ONLY=yapp_project    # build/sim/report/coverage.md + HTML

      coverage.md lists, per covergroup, covered / total bins, the holes (bins no run hit), every bin with its hits, the number of runs and the tests that hit it, and what each test adds (bins only that test hits). The committed report of the project is yapp_project/regression/coverage.md; the same data is the site page Coverage results.

    3. The annotated sources (HTML). genhtml (lcov) draws every collector's source with the hit count next to each bin line: coverage/yapp_project_tb/index.html. Lines there means "a bin on this line was hit"; a line with several bins (legal[], a cross) shows each one under Branches (+ hit, - hole).

    The project map shows the merged bins too: open a coverage collector (pkt_cov, gap_cov, coverage, hbus_addr_cov, hbus_bits_cov, hbus_data_cov, hbus_counter_cov) and its panel lists every bin with its hits and the tests that hit it; a hole is red, a click shows its line, and the panel links to the annotated source. The regression results pages say how many bins each test hit.

    The percentage is covered bins / bins of the covergroup, as Verilator's get_inst_coverage() gives it (the helper coverpoints of the Verilator cross count too); IMC weighs coverpoints differently, see what is not verified.

    Running with coverage (Xcelium)¶

    cd labs/lab10_cov/tb
make run TEST=coverage_test          # run.f already has -coverage U -covoverwrite
imc -load cov_work/scope/coverage_test

    In IMC (or SimVision → Windows → Tools → Coverage): Verification Hierarchy → uvm_pkg → …yapp_pkt_coverage, right-click → Cover Group Analysis, open the Items of yapp_pkt_cg.
